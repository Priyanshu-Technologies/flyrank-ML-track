Refresh / Content Opportunity Scoring

A machine-learning approach to prioritizing content pages for human review

Author: Priyanshu Sharma

Lane: Refresh / Content Opportunity Scoring

Dataset: FlyRank ML Internship dataset

Abstract

This study asks whether observable page-level search, engagement, visibility, and content signals can help prioritize which content pages should receive human review.

I evaluated a transparent rule-based baseline and a Logistic Regression ranking model using anonymized FlyRank content data.

The learned model was evaluated using Precision@50 and a client-grouped validation design to reduce the risk of client-level information appearing across training and test data.

The Week-4 baseline and learned model were evaluated on the same held-out test clients.

The resulting ranking is intended as directional decision-support for content review rather than a causal prediction of future performance or the outcome of a content refresh.

1. Problem Statement

Content teams have limited time for reviewing and improving pages. The practical decision is therefore not simply whether a page is "good" or "bad", but which pages should be investigated first.

The unit of analysis is a content page for a client. The output is a ranked review queue containing a model score, reason code, and suggested action.

A human editor can use this queue to investigate whether a page should be refreshed, expanded, protected, monitored, or considered for another content action.

A false positive can consume limited editorial review capacity, while a false negative can cause a potentially useful page to be overlooked.

2. Data

The analysis uses the anonymized FlyRank content-refresh starter dataset containing approximately 30,000 content observations across 32 clients and 44 columns.

The data contains observed search visibility, engagement, content, and performance signals over a 90-day observation window.

Target / proxy

The observed proxy target is is_declining_label, defined as 1 when trend_direction == "down" and 0 otherwise.

Excluded fields

  • trend_direction — used to construct the observed target, so it would leak the label if used as a feature.
  • trend_pct — derived from the same trend information and therefore excluded.
  • content_id — identifier only.
  • client_id — used for grouped validation only, never as a model feature.
  • Future-window outcomes — unavailable at the decision point and therefore excluded.
No client names, domains, URLs, private queries, credentials, or client-identifying information are presented in this paper.

3. Baseline

The first benchmark was a transparent rule-based score created in Week 4.

A page received a positive baseline score when days_since_last_update ≥ 180 and impressions_90d ≥ 500.

The baseline score was the page's observed impressions_90d value when both conditions were satisfied and zero otherwise.

Pages receiving a positive score were assigned the reason code stale_visible_page and the suggested action refresh_review.

The baseline provides a transparent benchmark that the learned model must beat rather than comparing the model against an arbitrary standard.

Exact evaluation metrics are generated by the reproducible notebooks and should be updated here after the final fresh run.

4. Methodology

Learned model

I used Logistic Regression as the first learned model because it is relatively simple, interpretable, reproducible, and appropriate for producing a probability-based ranking.

The predicted probability of the observed declining label is used as the ranking score.

Features

The model uses observable search, engagement, content, visibility, and traffic signals including:

  • search volume and competition
  • content age and days since last update
  • impressions, clicks, pageviews, sessions, and users
  • engaged sessions and scroll events
  • recent and previous-period performance signals
  • CTR and average search position
  • engagement, scroll, and AI-traffic percentages
  • content word count

Label-derived fields and identifiers were deliberately excluded.

5. Evaluation

The primary evaluation uses a client-grouped train/test split. All pages belonging to a client remain entirely within either the training set or the held-out test set.

The primary ranking metric is Precision@50 because the intended use is to prioritize a small review queue.

Error analysis

Model errors were examined as false positives and false negatives relative to the observed declining label.

False positives represent highly ranked pages that were not labeled as declining, while false negatives represent declining pages that received lower model scores.

These errors demonstrate why the ranking should be treated as a review-prioritization signal rather than an automatic editorial decision.

6. Interpretation

Logistic Regression combines multiple observable signals into a directional ranking score.

Its coefficients indicate which modeled features are associated with higher or lower predicted probability of the observed declining label, holding the other modeled features constant.

These are predictive associations within the dataset and should not be interpreted as causal effects.

An important practical finding is that a highly ranked page may still be a poor refresh candidate after human inspection. A page may already satisfy search intent, have strategic importance, or require monitoring instead of a content change.

Negative result

The Week-6 random-versus-grouped validation comparison produced no measured Precision@50 difference in the evaluation run. This is reported as a negative result rather than being interpreted as proof that the model is universally robust.

7. Ranked Recommendations

The recommended use of the model is as a ranked decision-support queue for content editors and SEO teams.

Priority Suggested action Human review
High Refresh review Check whether a genuine content opportunity exists.
High Expansion review Check content depth and search intent.
Medium Protection review Check whether existing performance should be preserved.
Lower Monitor Continue observation without immediate change.
Unusual Manual investigation Gather additional context before acting.

Human-review rule

Every model-ranked page should be reviewed by a human before a content change is made.

Reviewers should consider search intent, content quality, freshness, observed performance, strategic importance, and the risk of changing an already successful page.

What should NOT be automated

  • Automatically publishing a content refresh.
  • Automatically deleting or pruning pages.
  • Automatically changing search-intent targeting.
  • Automatically rewriting page content.
  • Automatically redirecting or canonicalizing pages.
  • Automatically claiming that a refresh will improve performance.
  • Automatically overriding editorial or strategic judgment.
The safest interpretation is: use the model to decide what to review first, not what to publish automatically.

8. Limitations & Honest Framing

The current target is an observed declining proxy rather than a genuinely future outcome.

The analysis therefore does not establish that the model predicts future page performance or that refreshing a page will cause performance to improve.

The model also does not predict or prove the behavior of Google's ranking algorithm.

Editorial strategy, business priorities, search-intent changes, and other information outside the modeled dataset may affect the correct decision for an individual page.

The results should therefore be described as observed, measured, directional, and useful for decision-support rather than causal or guaranteed predictions.
